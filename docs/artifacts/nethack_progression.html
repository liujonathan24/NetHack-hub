Read this cohort with care

All 24 endgame games belong to a single player. They were picked as the cheapest to decode (one session file each), and the only NAO players who finish a game inside one sitting are the very strong ones. So this is one expert's trajectory shape repeated, not a population — which is exactly the gap the DeepMind top-10 corpus fills. Treat the median line as "what a strong run looks like", not as a percentile of humanity.

Which metric models "how close am I to finishing"?

Use min. Tested on the 2,570 complete top-10 games, of which 131 reached Dlvl 50. At turn 2,000, 758 of 1,677 games in play score above zero on max but exactly zero on min — progress on one axis only. Just 3.3% of those go on to reach the end, against 11.5% of the rest. A metric that awards a score to runs that finish at a third the rate is not measuring closeness to finishing; min is what catches them, and it is the variant that punishes the under-levelled diver our own agents keep becoming.

Two honest qualifications. Max is marginally the more linear of the two in elapsed progress (pooled R² 0.41 vs 0.38; median per-game 0.74 vs 0.71), so if you want the straightest line rather than the truest one, that is max. And neither variant separates eventual finishers well in mid-game: AUC hovers near 0.5 at every turn checkpoint, and at turns 5k–10k the median non-finisher is actually the deeper one (16.13% vs 12.56% at turn 10k). Among experts, being further along at a given turn does not mean you are more likely to finish — the fast divers are the ones who die. Treat a fitted line as a description of pace, not a completion forecast.

Winners only restricts each population to the games that actually ascended — 433 in the NAO population (from the xlogfile death field) and 298 among the complete top-10 games (from a status-line and message-text scan validated at precision 1.000 / recall 0.998 against the xlogfile). Our agent has none, so it draws nothing under that toggle: no rollout has ever come close. On the best-fit line: it is fitted to each population's mean, in whatever x-space is displayed (so on the log axis it is a fit against log-turns), and only over the range where at least a quarter of that population is still playing — past that point every curve is carry-forward flat and would drag the slope toward zero for reasons that have nothing to do with play. R² is printed at the line's end. Use the min variant for this: see the note below the table on why. Agent cells are GLM-5.2, 200 LLM calls, BBOX_MIN and its neighbours, seeds 0–4; e6_vision/prime_agent is the 8.88% headline cell and e6_vision/claude_code the 5.85% one. The top-10 corpus is filtered to sessions using a default 24×80 interface, so a game whose other sessions were filtered out can appear truncated; only games whose opening session is present (turn ≤ 5) are counted here. Our agent rollouts are capped at 400 game turns by configuration, which is why that line stops where it does — it is a budget boundary, not a skill ceiling.

Games that actually beat NetHack

Ascension is the win condition, and it is rare enough that most agent work never sees one. In the downloaded corpora there are 731: 433 among the 23,860 NAO population games and 298 among the 4,480 complete top-10 games — a 1.8% win rate for the general population against 6.7% for the ten strongest players. Detection was validated against the xlogfile at precision 1.000 and recall 0.998, with zero false positives.

A win takes about 42,000 game turns — median ascension turn 43,040 for the population and 41,671 for the top 10. Our agents are configured for 200 LLM calls and reach a median of 333 game turns. Closing that gap is roughly two orders of magnitude, and it is a turns-per-call problem before it is a reasoning problem.

One detection subtlety worth knowing

The message "You offer the Amulet of Yendor to…" is not proof of a win: offering it to the wrong deity prints that same line and ends the game as escaped in celestial disgrace. There are exactly two such games in the scanned set, and both are correctly excluded. The evidence used instead comes from pray.c: "You ascend to the status of Demigod(dess)", "An invisible choir sings…", and the role-dependent farewell — which is Farvel for a Valkyrie and Sayonara for a Samurai, not Goodbye.

How the curves were built

  • Decode. A NAO ttyrec is a 12-byte little-endian header (sec, usec, len) followed by raw ANSI, bz2-compressed. Frames are replayed through a VT emulator to rebuild the 24×80 grid; the status block is parsed off it. No nle install needed. 88.7% of frames carry a parseable status line.
  • Reconstruct. A ttyrec is a login session, not a game. There is no game ID, so games are assembled by bracketing each session file's timestamp inside the xlogfile's starttime–endtime window for that player.
  • Validate. Derived max Dlvl matches the xlogfile for 96.5% of the 28,040 decoded games. Assigning each session file to exactly one game matters here: the naive rule of "every game whose start–end window contains this file" gives a file to several games at once, because a saved character resumed later has a window spanning everything in between — the longest measured is 4.7 years. Exclusive assignment moved validation from 95.8% to 98.4% on the pilot slice.
  • Score. The vendored BALROG achievement table, on running maxima of Dlvl and Xp. Depth is capped at Dlvl 50 — no plane or ascension bonus — so 80.68% is the ceiling on this page.
  • Known gaps. The Quest prints Home N instead of Dlvl:N and is skipped; polymorph replaces Xp: with HD:; a status line caught mid-redraw can report a truncated turn counter (one game in 28,040 needed clamping). Every game in this shard is NetHack 3.4.3, which prints End Game for the Elemental Planes — the per-plane names only arrived in 3.6.2, so a matcher written against modern NetHack silently misses every Elemental-Plane frame here.
