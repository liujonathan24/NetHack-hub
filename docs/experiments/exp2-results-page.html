Headline

Prime Agent beats Claude Code on both action surfaces

On the NetPlay skill surface with GLM 5.2, Prime Agent reaches dungeon level 5.00 to Claude Code's 4.00. On BALROG's 80-keystroke surface — a completely different action space — the same ordering holds, 2.20 to 1.20. Two surfaces agreeing is the most useful thing these runs produced: it suggests the gap is a property of the harnesses rather than an artifact of our skill layer.

The honest caveat is that the error bars overlap. At n=5 per cell, neither the depth nor the BALROG difference is statistically established. The consistency across surfaces is what carries the claim, not either measurement alone.

Why b80 scores low — it is a budget artifact, not weak play

A NetPlay skill batches many game turns into one LLM call. A raw keystroke buys about one. So the call budget is the game-turn budget, and the b80 arm played roughly half as much NetHack while spending nearly four times the calls.

netplay_true · 176 calls8.5×
balrog80 · 672 calls1.2×

Game turns purchased per LLM call, GLM · Claude Code. Two of five b80 seeds also hit the 2 h wall-clock cap before reaching 1,200 calls — BALROG's own runs used 1,057–2,231 calls, so this configuration could never have replicated 6.77% regardless of model.

What I'd do next

  • More seeds before any claim ships. Every headline difference here overlaps within error at n=5. Extending the two GLM cells to 16 seeds is the single highest-value spend.
  • Guard the output directories. best_fixed already held turn files from two earlier attempts; globbing them would have reported n=15 with a contaminated mean. This is the fourth occurrence of a relative-path or stale-output bug — the launcher should refuse to write into a non-empty turns/.
  • Fix the Flash early-exit. Flash's Claude Code process exits cleanly after ~14 calls on the 80-key surface, while the same model plays hundreds of calls on the skill surface. That is a harness bug, not a model limit.
  • Make the provider transient non-fatal. Provider finish_reason: error still kills Prime Agent rollouts outright — it surfaces as a subprocess exit, so the rollout-level retry never engages.
  • Re-run the encoding b80 sweep on 98f77ba. Its current results measure the wedge, not the encoding.
